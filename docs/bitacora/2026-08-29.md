# 2026-08-29 — Qdrant como servicio systemd (sobrevive reboots)

## Problema
Al verificar el dashboard de `devops-multiagent` (idea 4), la eval de RAG falló: `search_knowledge` no podía conectar a Qdrant. El contenedor estaba `Exited (143)` desde 34h antes — se había lanzado a mano con `podman run` (ver README anterior), sin ninguna unidad de systemd detrás, así que no volvió a levantarse tras el último reinicio del server/workstation.

## Fix: Podman Quadlet, no `podman generate systemd`
Se descartó `podman generate systemd` (ruta antigua, deprecada desde Podman 4.4+) a favor de **Quadlet**: un archivo declarativo `.container` en `~/.config/containers/systemd/`, que un generador de systemd (`podman-user-generator`, ya presente en el sistema) traduce a una unidad `qdrant.service` real en cada `daemon-reload`.

`systemd/qdrant.container` (copiado también a `~/.config/containers/systemd/qdrant.container` para que systemd lo vea):
- `Restart=always` en `[Service]`.
- `WantedBy=default.target` en `[Install]` — junto con `loginctl enable-linger` (ya activado desde el watcher de `devops-multiagent`), arranca en boot sin sesión de usuario activa.
- Mismo bind mount que el contenedor manual (`qdrant_storage/`), incluyendo el mismo `ContainerName=qdrant`.

## Migración sin perder datos
1. `podman stop qdrant && podman rm qdrant` — el volumen (`qdrant_storage/`, bind mount a disco) no se toca, los datos viven ahí, no en el contenedor.
2. Escribir el `.container`, `systemctl --user daemon-reload`, `systemctl --user start qdrant.service`.
3. **No hace falta `systemctl --user enable`** — a diferencia de una unidad `.service` normal, Quadlet resuelve el `[Install]` en el propio generador y agrega la unidad a `default.target.wants` automáticamente en cada `daemon-reload`. Intentar `enable` a mano falla con "transient or generated" (esperado, no es un error real).

## Verificado
- `GET /collections/bitacora` tras la migración: `points_count: 17` — mismos datos que antes, el bind mount preservó todo.
- Suite completa de evals de `devops-multiagent` (`uv run python evals/run_evals.py`): 9/9, incluyendo el escenario de `search_knowledge` contra Qdrant real.
- `systemctl --user status qdrant.service` → `active (running)`, ya listado en `/run/user/1000/systemd/generator/default.target.wants/`.

## Nota
El `Volume=` en `systemd/qdrant.container` usa ruta absoluta (`/home/gaelsg/...`), específica de esta máquina — igual que `.env.example` ya asume `~/projects/...` para quien clone el repo. Ajustar esa línea si se despliega en otra máquina.
